# CS2 MVOU Tournament

Статический сайт турнира с публичной страницей, открытой панелью редактирования, синхронизацией через Supabase Realtime и отдельным сервисом map veto для капитанов.

## Структура

- `index.html` — публичный экран турнира.
- `admin.html` — редактирование команд и результатов.
- `veto-admin.html` — создание приватной комнаты выбора карт и ссылок капитанов.
- `veto.html` — синхронная комната жеребьёвки, банов, пиков и выбора сторон.
- `assets/styles.css` — общий адаптивный интерфейс.
- `assets/veto.css` — отдельный iGaming-интерфейс map veto.
- `js/data.js` — правила турнира и расчёт сетки.
- `js/render.js` — безопасный рендер публичной и административной страниц.
- `js/supabase.js` — загрузка, конкурентное сохранение, Realtime и Storage.
- `js/veto-api.js` — защищённые RPC-вызовы и Realtime комнаты.
- `js/veto-rules.js` — актуальный пул и последовательности BO1/BO3/BO5.
- `js/config.js` — публичные параметры проекта Supabase.
- `supabase/schema.sql` — таблица, RLS, Realtime, Storage и пустой турнир.
- `supabase/veto_rooms.sql` — комнаты veto, хэши токенов, атомарные ходы и Realtime-сигналы.

## Формат турнира

Групповой этап — круговой BO1 для пяти команд. Четыре команды с наибольшим количеством побед выходят в полуфиналы BO3. Победители полуфиналов играют финал BO3, проигравшие — матч за третье место BO3.

## Map veto

Организатор создаёт комнату и получает три ссылки: по одной для каждого капитана и одну административную. Токен ссылки после первого открытия переносится в `sessionStorage` и удаляется из адресной строки. В базе хранится только SHA-256-хэш токена. Оба капитана согласуют BO1/BO3/BO5, первая команда вызывает орла или решку, победитель выбирает роль Team A/Team B, после чего сервер последовательно разрешает только корректный бан, пик или выбор стороны. BO1 и BO3 следуют Major Supplemental Rulebook; BO5 — локальное расширение для семи карт.

## Безопасность

Сайт использует только publishable key. Политики RLS разрешают публично читать и обновлять единственную строку `main`, но запрещают вставку и удаление строк. JSON ограничен 128 КБ и проверяется по базовой структуре. Ревизия изменяется триггером и защищает от тихой перезаписи параллельных правок. Storage принимает только пять фиксированных WebP-путей и файлы до 1 МБ. CSP ограничивает внешние скрипты, подключения, изображения и iframe утверждёнными источниками.

Открытое редактирование означает, что любой человек, получивший URL панели, технически может менять результаты. Для настоящего ограничения сотрудниками потребуется подключить Supabase Auth и корпоративный домен.

Комнаты map veto защищены сильнее основной панели: прямого доступа к таблице комнат у браузера нет, секреты хранятся только как хэши, а каждый ход проходит проверку роли и ожидаемой ревизии внутри одной короткой транзакции. Публичной для Realtime остаётся только таблица сигналов с UUID комнаты и номером ревизии — без названий команд, токенов и результатов.
